# 每日状态与历史关系的候选承载契约

研究结论：现有每日 profile 的 TRUE-witness 投影无法还原 FALSE/UNKNOWN；现有派生关系 Binder 只绑定同一 User，不能直接承担按事实日期选择另一个历史目标。候选需要分别保存完整每日状态和独立历史来源，再生成有限的对象查询、解释、发现与 MCP 接口。业务决策尚未获得答复，本文不是实现契约或插件验收。

沿用 [OSSIE-REQ-001](../../../ossie-execution-research.md) 和[完整 P1 计划](../../../../ossie-duckdb-plan.md)，不另建需求列表。前一[程序承载研究](../p1-program-research/research.md)是当时的实现前记录；其关系、多事实和观察行窗口已随后实现，但状态与历史仍未完成。固定规范是本地 Ossie 0.2.0.dev0 快照 `8dd6732da354f22ca71f16d82626a46039ecdcd9`。

## 每日状态：候选语义和用户分母

待确认的候选归约如下。T/F/N 表示产品范围内同一 User、同一天存在 TRUE/FALSE/NULL 观察，重复同值不改变这个候选结果。

| 当日不同观察值 | 候选状态 |
| --- | --- |
| 无观察 | UNKNOWN |
| T、T/F、T/N、T/F/N | TRUE |
| F | FALSE |
| N、F/N | UNKNOWN |

不向缺失日期延续前一状态。固定[表达式规范](../sources/apache-ossie/core-spec/expression_language.md)没有替应用确定这一观察归约政策。普通 SQL 对照明确发现：`bool_or(FALSE,NULL)` 为 FALSE，而候选政策为 UNKNOWN；直接采用忽略 NULL 的聚合会改变问题含义。

候选请求明确包含起止自然日、产品范围和用户域声明。技术接口可以显式拒绝未知域，不能默默将观察行数当用户数。尚需决定用户域是整个冻结观察捕获中的去重 User，还是请求日期/产品范围内实际被观察的 User。前者会把仅有范围外观察的 User 列为 UNKNOWN，后者不会；两者都不代表完整注册用户。

候选每日对象保留 `(User类型,完整User身份,自然日,状态)`，统计同时报告用户域、天数及每种状态数量。变化对象保留前后自然日和两种状态，允许核对全部九种状态对及真实成员。建议首片只比较请求内相邻自然日：单日没有变化对，首日没有隐式历史前驱；若业务要比较请求起日前一天，需明确声明并额外捕获。

旧“每天都合格”的 TRUE-witness 接口继续保留原行为，不能把新 UNKNOWN 处理方式静默移植到旧接口。新能力发现须分别声明：自然日状态、请求内相邻变化、观察行 LAG/ROWS，避免把观察行前值解释成前一天。

## 输出和计算预算

日历候选沿现有每日接口的 0001—9999 年、最多 366 个请求自然日。此限制是项目首片范围，不能称为 Ossie 或 DuckDB DATE 的完整范围。

若 U 个 User、D 天的响应同时保留全部状态和全部相邻日对，状态为 `U×D` 行，变化对为 `U×(D−1)` 行，总量为 `U×(2D−1)`。27 个 User、366 天只有 9,882 个状态，却有 19,737 个合计对象。候选应在计算/分配前以安全整数核对合计预算；若只返回发生变化的对，也不能靠最终过滤掩盖中间计算规模。

建议分别声明输入行/捕获字节、日历规模、中间和完整输出对象数、最终 JSON 字节；沿用完整返回、不截断、不分页。候选 10,000 合计对象和 1 MiB 响应仍需原生边界实验后冻结，当前枚举不证明实际内存、耗时或编码预算。

## 历史关系：来源身份和目标实体

待确认的候选为有限 DATE 半开区间 `[start,end)`：事实日期等于 start 匹配，等于 end 不匹配；缺口没有关系 link。来源按 User 及有效期关联，但目标必须来自声明的带类型角色映射，不能将恰好同值的任意字符串当实体。

[本体规范](../sources/apache-ossie/ontology/ontology.md)将关系 link 定义为集合且不含 NULL，角色约束可规定函数性；这不决定原始历史记录是否重复。候选来源主键须在固定 schema、映射和物理捕获中一致。技术选项是显式 `history_record_id`：相同 ID 重复拒绝；不同 ID 的同区间同目标记录各自保留来源身份，形成关系时再按完整 link 去重。此方案尚未冻结，不能把源重复错误与推导集合去重混为一谈。

待确认的冲突政策是同一 User 的不同目标区间重叠即整批拒绝加载；应检查完整历史捕获，不能只检查实际有事实的日期/User。研究样例中 B 没有事实，但两个历史目标仍重叠；先按事实筛选会隐藏冲突。失败、第二源捕获失败、取消和超预算都须保留旧 parent snapshot。

同目标重叠及相同区间不同 ID 的保留/拒绝策略仍需固定。即使最终目标去重为一个，朴素事实×区间连接也可能产生巨大中间 bag。建议研究按 User 分组的区间端点检查与有界索引/扫描，不通过无限连接再去重控制资源。有限端点意味着 `start<end`、NULL/infinity 拒绝；最大日期没有可表示的更大有限 exclusive end，不能偷偷加一天或补无限端点。

## 最小接口和验收边界

候选采用明确选择的新时间 program，复用冻结捕获、hash、原子发布与错误契约。每日输入保留原观察真假/NULL，历史输入独立捕获事实及有效期两个来源；两个组件均不能通过放宽旧 profile 获得隐式新行为。具体 profile 名、JSON 字段和函数名在业务口径及固定 schema 可承载性审查后冻结。

查询输出完整状态或历史关系身份；compile 输出实际日期/产品/用户域、归约/区间匹配阶段和预算，不执行对象计算。发现及 MCP 明确所支持的唯一候选口径，拒绝模糊日历、范围外前驱、开放区间、多目标冲突、任意跨图路径与未声明目标映射。拒绝边界也须有实际原生、SQL、MCP 和旧 profile 回归证据。

最小验收应覆盖空域、七种非空真假/NULL 组合、范围外产品/User、闰日跨月、完整九种相邻状态对、相同人数但不同成员；历史覆盖起点/终点、邻接/嵌套、同/异目标重叠、原始重复身份、缺口、无事实冲突、大小写及完整字符串身份；资源覆盖状态加变化总量、转义 JSON 与中间规模；生命周期覆盖 prepared 保留、替换失败及取消恢复。真实模型调用未授权，只设计对应无模型演练与独立 oracle。

## 本轮证据与局限

[oracle.json](oracle.json)由 [research_p1_time.ts](../../../../scripts/research_p1_time.ts)执行，绑定研究脚本、两份固定规范和当前 macOS 产物 SHA。它将八种值集合、有限区间边界和冲突与独立 TypeScript 枚举比较；历史示例保留六条来源记录，普通连接四行，集合 link 三条。整批数据包含未被事实观察到的冲突，因此这些 link 只是 SQL 研究输出；按候选加载政策应拒绝整批，不能拿它们冒充已成功加载。

首轮参数绑定误用只接受字符串的辅助接口，类型检查和研究运行均失败，原脚本及重现日志保存于私有证据目录。修正为闭合枚举生成的 SQL 常量后通过，没有扩大辅助接口。此研究没有执行新的 native temporal loader/Binder，没有证明实体映射合法、产品语义、算法复杂度或运行资源，也没有获得业务答复。

本轮复用单一只读 advisor-escalation 审查；采纳三值信息保留、typed 历史目标、来源与 link 身份区分、全批冲突检查和总量/中间预算反例。Lead 核对本地固定来源及上述实际输出。请求 Astra/high；实际 backend、effort、usage 和 billing 未知。完整 P1 状态与历史实现仍待业务决策，其他已完成能力不替代它们。
