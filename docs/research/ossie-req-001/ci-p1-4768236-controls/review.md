## Linux 失败与根因边界

失败步骤为 `Prepare rehearse and replay three P1 scenarios with bounded
failure controls`，错误是 `ordered event expected: simulation_response`。
堆栈定位 `p1_agent_replay.ts` 的有序事件读取：重放器期待模拟响应，实际
遇到的事件种类未出现在日志里。后续 P1 模拟传输、观察 MCP、观察无模型
演练被跳过，不能记为本次 Linux 成功。

源码存在一个明确的边界敏感路径：只有下一条是 failure，且记录的
`elapsed_ms >= milliseconds`，重放才模拟超时；否则它继续要求模拟响应。
执行侧以计时器取消工作，以 `Date.now()` 记录耗时。源码没有证明计时器
触发时记录值一定满足这个阈值。若合法超时被记录在 limit−1，能够进入
与本次相同的报错路径；事件读取失败还会提前推进 cursor，遮蔽原失败。

这是**领先假设，不是已确认的 CI 根因**。日志没有控制场景 ID、实际事件、
耗时或原终止原因；缺响应、事件顺序或其他终止错误也可能触发同一断言。
Linux 的私有原始轨迹按既有隐私合同没有上传，因此不能凭当前公开证据
