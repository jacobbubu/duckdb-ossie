# DuckDB ossie 扩展升级与本体执行需求

日期：2026-10-08  
状态：需求草案，可用于实现范围评审。当前仅生成临时文档，不授权修改扩展、现有项目、发布或部署。  
本地需求记录：OSSIE-REQ-001；问题、范围与验收均在本文件维护，不另建实施 backlog。

## 1. 目标与判断

以 DuckDB 保存全部试验数据，复用 ossie 扩展的语义查询编译与执行能力，补齐受约束的本体定义到查询的执行路径。

第一阶段证明：业务概念及规则能够实际改变查询范围与计算结果，并且查询采用的规则可检查。仅成功加载本体文件、生成 SQL 或由 Agent 阅读规则，不算本体执行完成。

以 QwenPaw-Data 的 DataBridge GAAP 示例作为首个可复现用例；它足以验证基础指标与简单概念派生，不足以独立覆盖多表关系、多期实体状态及复杂推理。

## 2. 输入与现有证据

- 当前扩展加载旧的 `semantic_model: [...]` 格式，仅允许一个模型；表达式选择 `ANSI_SQL`，使用 DuckDB 解析器。
- Apache core 文档记载已发布版本为 `0.1.1`；当前 main 是可变、未发布的 `0.2.0.dev0`，已改为根级单模型。`OSSIE_SQL_2026` 表达式文档状态为 Proposed Final。
- 当前扩展已有字段表达式展开、关系图、粒度推导、SQL 编译和执行；多聚合粒度、可能放大数据的连接和歧义路径会被拒绝，连接目前全部为 INNER JOIN。
- 当前公开解析器未实现完整 ontology/mapping 执行。升级 core 文档格式，不等于实现概念派生、约束或递归关系。
- DataBridge 示例为单表 `dws_gaap_di`，475 行，日期为 2026-03-01 至 2026-03-15；每行 user_id 唯一。
- 示例有效用户条件为 `ytd_gaap >= 10`；现有指标公式重复写入该条件。项目明确说明当前 KG 规则不能直接转为 SQL。
- 原始示例的有效产品 X 用户逐日平均 GAAP，预期 2026-03-10 峰值四舍五入后为 45.89 USD。该数值来自示例记录，本需求编写时未重新运行验证。

上述是文档和源码证据，尚无本次扩展构建、DuckDB 导入或运行结果。

## 3. 第一阶段必需能力（P0）

### R1. 固定规范与执行器版本

1. 固定 Apache Ossie core、ontology、mapping、expression 文档的具体提交，以及 DuckDB 和扩展提交；保存来源与内容哈希。
2. 明确已发布版本兼容范围和开发规范试验范围；不能以“支持最新 Ossie”代替能力说明。
3. 保留现有有效旧格式模型回归，并增加固定开发快照的新格式 loader；两个入口映射到经过验证的内部表示。
4. 冲突格式、未知版本或无法解释的执行语义必须明确拒绝。描述性扩展可保留但不执行；不得将“保留字段”声明为“支持其语义”。

### R2. Core 模型与元数据适配

1. 支持目标快照的根级单模型结构，检查名称、数据集、字段、指标、键与关系引用。
2. 正确处理 datatype 与时间维度默认值，支持 ai_context 的字符串和对象形态、synonyms、instructions、examples。
3. 保留模型与字段的说明、标签、单位扩展等业务元数据；单位若来自扩展，应说明其来源，不擅自推断或转换。
4. 发现接口应说明实际可执行的对象、支持方言和限制；元数据中的自然语言说明不自动变成计算规则。
5. 按规范逐字段核对映射，不以新旧 JSON 包装可互转证明内部语义一致。

### R3. 可验证的表达式执行子集

1. 支持固定版本 `OSSIE_SQL_2026` 的明确子集，保留已支持的 ANSI_SQL 路径；公布支持、需转换、不支持的语法和函数。
2. 首批覆盖字段引用、算术与比较、布尔逻辑、CASE、SUM、COUNT、COUNT DISTINCT、AVG、NULLIF、COALESCE，以及用例所需的日期和类型转换。
3. 明确名称作用域、大小写与引号、NULL、空集、除零、数值精度、日期边界及时间类型行为；依据规范或声明的实现限制验收。
4. 方言选择必须确定、可查看。不能仅把 OSSIE_SQL_2026 标签改成 ANSI_SQL 后直接执行。
5. 校验允许的 AST、函数及引用；不能因 DuckDB 能解析而接受规范或本实现禁止的构造。未知函数不能静默透传。
6. 窗口函数只有在其语法、执行阶段和结果语义验证后才能进入支持范围。未覆盖语言要求的全部必需能力，不宣称完整符合该语言。

### R4. 业务概念、身份与数据映射

1. 加载固定 ontology/mapping 快照中首批支持的概念定义，将概念及属性映射到 DuckDB 中的数据集、字段与实体键。
2. 支持首个用例的 User、ValidUser，以及产品、地区、用户类型等属性绑定；具体文件结构在实现设计中确定，不在此发明标准字段。
3. 支持由明确谓词派生的非递归概念人群，以及简单继承关系的身份保持和已支持属性继承。
4. 分开处理实体身份与事实记录粒度。原始示例的全表唯一 user_id 不能证明真实日快照应使用同一主键设计。
5. 给定概念和过滤可查询对象；给定概念范围和指标可查询聚合。接口名称尚未确定，不承诺现有 ossie_query 已具备概念参数。
6. 概念规则、身份和绑定缺失或冲突时明确报告，不能让 Agent 随意挑一个解释。

### R5. 概念规则真正进入查询

1. ValidUser 的有效性条件只在受版本管理的业务规则中维护：原始用例为 ytd_gaap >= 10。
2. 查询有效用户平均 GAAP 时，执行器组合概念范围、用户过滤和指标定义，自动生成对应 SQL。
3. 平均 GAAP 指标不再重复维护有效用户阈值；改变阈值后不修改指标公式、Agent 提示词或执行代码，即可执行新的定义。
4. 规则适用对象、筛选阶段、时间基础及版本必须明确。记录级分类不能自动冒充跨日期实体级分类。
5. 区分 derived_by 的派生含义与 requires 的约束含义。不能把 requires 一概转成 WHERE 后静默删除不合格记录；未实现的约束语义应拒绝或明确报告未验证。
6. 本体文件、指标模型和 mapping 的自然语言及可执行规则不一致时报告冲突。示例中的“活跃付费用户”描述不能凭 ytd_gaap 阈值额外证明活跃或付费状态。
7. 模型规则是审核后的定义；请求方不能借过滤、方言选择或自然语言覆盖正式公式与规则。

### R6. 查询规划与粒度正确性

1. 保留歧义路径、多粒度及 fan-out 拒绝机制，除非对应的新规划已通过独立数值验证；不能为跑通示例关闭保护。
2. 明确每个聚合的数据集、粒度、连接路径和作用范围；多表查询必须区分指标粒度与实体身份。
3. 基数推导依赖的声明键应在试验数据预检中核实；键声明本身不证明实际数据唯一。
4. 对无匹配关系和 NULL 外键定义处理策略。关系基数不能自动决定 INNER/LEFT；策略影响结果时必须明确并验证，无法确定时拒绝。
5. 第一阶段只支持明确列出的安全连接形态；复杂跨粒度指标不作为新格式加载的隐含承诺。

### R7. 可检查的编译与执行结果

1. 保留 compile/query 同源编译，能查看实际执行 SQL。
2. 提供机器可读的编译说明：概念、规则、指标及模型版本/哈希，实际过滤与时间范围、方言、粒度、连接路径和已知限制。
3. 执行说明必须取自实际编译与执行状态，不能只回显请求参数。
4. 结果与 SQL、定义快照以及数据导入批次关联；声明排序、空结果和截断行为。数据快照记录与执行引用可由服务层维护，但插件要暴露所需信息。
5. 概念发现、对象查询与指标查询具有可区分的结果契约；错误包含对象、阶段、原因和缺失能力。

## 4. 验收用例与证据

| 用例 | 操作 | 验收依据 |
|---|---|---|
| A1 原始查询基准 | 导入原始475行，查询产品X有效用户逐日平均GAAP | 与独立SQL/期望结果逐日对比；复核3月10日45.89及人数、金额 |
| A2 规则驱动 | 同一规则资产阈值从10改为20，指标公式和Agent提示词保持不变 | SQL实际条件和结果同步改变；与独立基准对比；使用两个定义版本 |
| A3 概念对象与指标一致 | 查询有效用户对象，并查询相同范围平均值 | 对象范围、计数、金额、平均值相互核对；避免混用实体与记录 |
| A4 分组和下钻 | 按地区、用户类型分组，再钻取具体组 | 继承父级产品、时间及有效性规则；以完整分组核对金额与人数 |
| A5 空集和边界 | 加入阈值相等、NULL、无匹配及空集案例 | 结果符合声明的规则、空值和连接策略；无静默改口径 |
| A6 安全连接 | 增补事实/维度表，并构造重复键、fan-out和歧义路径 | 安全连接数值正确；不支持的查询明确拒绝 |
| A7 定义追溯 | 在同一数据快照重跑固定定义版本 | 能定位实际SQL、规则及绑定；同条件结果可复现 |
| A8 格式和方言 | 新旧core形态、方言选择及非法构造 | 支持路径通过；不支持语义在执行前明确失败 |

独立基准不能只比较两个共用编译器的 loader。测试数据需要可人工推导的结果或独立查询，并核对对象、统计范围、单位、计算与数值。

平均值不满足分组可加性：不能相加地区均值、不能用未加权的分组均值恢复总体。分组核对至少保留 SUM 与 COUNT；均值变化分解需另有明确算法。

原始数据保持不变；追加边界、多表和多期数据另存为派生 fixture，记录生成方式和哈希。现有 smoke test 使用模型 stub，不证明真实 Agent 自主选择与回答正确。

## 5. 后续能力（P1，独立评估）

- 补齐不同粒度分别聚合后再组合的指标；验证多事实表和复杂人群筛选。
- 扩展两个月及同一用户跨日期数据，验证有效性状态变化、历史关系有效期和时间窗口。
- 扩展声明明确、可验证的非递归派生关系和约束检查。
- 按业务需求扩大 OSSIE_SQL_2026 函数及窗口支持，持续公布兼容矩阵。
- 完整对象查询接口、解释接口与 MCP 集成按实际调用契约补齐。

这些是可见的后续需求，不属于第一阶段已经完成或默认授权的工作。

## 6. 职责边界与暂不纳入

插件负责：模型与规则加载、受支持语义的解析与编译、查询规划、DuckDB执行，以及真实编译/执行信息输出。

服务或Agent负责：自然语言理解、知识检索、方法编排、贡献/异常等分析算法、事件证据引用、图表与报告。服务维护可信身份、访问范围、导入快照及执行记录；不能把Agent填入的metadata当作授权。

首阶段不要求：通用OWL推理、一般递归规则与否定语义、全量Ossie规范符合性、跨源联邦查询、图数据库、LLM因果证明、自由SQL替代注册指标、自动发布社区扩展。

“解释3月10日峰值”中的事件材料可作为来源引用；不能把检索到的故事当成算法证明的因果。直接从原始表查询的收入与GAAP值也不能未经确认互换业务含义。

## 7. 完成条件与下一步

完成条件：固定版本下，A1—A8相关支持路径通过，拒绝路径符合契约，语义范围和偏离记录明确；能够展示一次规则驱动的完整查询与证据。仅构建成功、schema校验通过或SQL可解析不构成完成。

剩余必要工作：确定目标spec提交和内部模型映射；审阅DataBridge规则及字段语义；确定概念/对象查询契约；建立独立fixture与预期结果；构建与运行验证。
