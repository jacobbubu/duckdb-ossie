# 历史完整关系查询与逻辑解释

历史 profile 新增 `ossie_history_links_json` 与 `ossie_history_links_compile`，
以冻结的 User/DATE/product 观察查找历史目标；同目标多个 record_id 不重复输出，
有效期起点包含、末点不含，缺口没有关系。请求日期/产品只筛观察，不掩盖载入时
全历史的冲突。接口和拒绝边界见[使用契约](../../../population-history.md)。

[完整逐记录枚举核对](verification.json)与[产物 receipt](receipt.json)绑定
macOS ARM64 产物 `d51854132706e00d5bd150d79ea55d25d22fe6cca0d2f2e9ce8cadb4421845bf`。
7 项控制/28 项拒绝覆盖完整关系及排序、大小写/NUL/转义、BC/宽年份/有限日期
孤立下界、同目标来源重叠、不同目标相接与缺口、范围/产品筛选及空来源。
10,000 条链接按完整身份逐条比较，未以数量相等代替成员相等。

原始请求恰好 16 KiB 可用，多一字节拒绝；包含请求范围、元数据及转义的完整
结果恰好 1 MiB 可用，多一字节拒绝并可恢复。大目标字符串由不可变索引持有，
查询不按观察行重复复制目标；该控制不承诺所有内存分配或并发资源的总上限。
compile 仅绑定三列实际类型，未扫描、匹配或计算链接，不能当物理计划/可重放 SQL。
计划和结果保留相同范围及六项追踪值。

原生捕获测试现为 482 检查，threads=4/1；四个查询阶段的确定性取消返回原生
INTERRUPT，恢复后完整结果一致。prepared links/plan 的完整 JSON 与绑定时相同，
重载及删两源后仍可读取并耗尽；新查询读取新父。这不证明所有引用释放后的
无泄漏。其余六原生 runner、29 SQL/1,070 断言、138 Bun/723 expects、类型、
TS/C++ 格式及架构通过。相同产物上的 P0、观察/每日集合/状态/关系/多事实 SQL、
五组旧 MCP 与无模型封存重放均通过。

失败日志与源码/报告共 337 私有原件由清单绑定。有限 INT32_MIN 日期可格式化，
但固定 DuckDB 的文本日期解析拒绝它：来源 fixture 改用 epoch 整数运算，接口
显式接受该精确规范文本；没有缩小有限日期域。初次 fixture 参数替换遗漏、错误码
预期、未匹配用例的 SQL filter、原生 runner 路径参数失误均保留，不计入通过证据。
旧加载 receipt 保留当时状态和 SHA；此次新 receipt 不覆盖旧原件。

CI 已加入实际历史 links/compile 验证入口，但尚未推送或远端运行。历史 MCP、
严格 decoder、无模型演练、新代码 Linux/tidy 和原五项 P1 统一收口仍必需。
