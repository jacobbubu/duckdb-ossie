使用已有本地Ubuntu24.04.5镜像、Bun1.3.11，隔离容器禁网络。探针在容器本地文件系统创建根目录与内层目录0700、文件0600；调用原测试的`fs.cpSync(...,{recursive:true})`，逐项核对模式与字节。每种umask独立重复三次，源目录不包含实际配置或模型证据。

| Linux ARM64 / 022，3次 | 根/内层均0700 | 根/内层均0755 | 均0600，字节一致 |
| Linux ARM64 / 077，3次 | 根/内层均0700 | 根/内层均0700 | 均0600，字节一致 |

## 最小修复

只修改`verify_p1_agent_offline.ts`的末尾来源变化控制：在新的测试目录显式创建0700目录，以0600和独占写入复制已验证清单中的原文件及原seal。复制的是原始Buffer字节，不重新序列化或重新封存。复制后先完整verifyArchive，并与原seal比较，再开始异步公开摘要导出与刻意修改run.json。

新增两个控制：合法副本保持原seal并通过严格归档验证；根目录、内层目录与文件分别放宽权限时必须拒绝，恢复后再次通过。原异步来源变化控制继续要求`archive byte hash mismatch`或`source snapshot changed`，不接受权限错误替代、不宽化错误正则，也不通过全局修改umask取绿。

权限拒绝和来源字节拒绝是两个边界。新的副本创建先满足权限合同，随后来源变化才能检验目标边界。此测试仍不构成任意文件系统并发竞争的安全证明。
