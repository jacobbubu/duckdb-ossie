# P1 剩余能力的有限承载方案

本轮结论：下一实现切片采用独立、显式选择的关系执行 profile，在现有冻结快照基础上保存带类型的关系声明和依赖；保持三个旧 profile 的行为。不同粒度事实各自聚合，再在声明的共同对象域组合。时间窗口按观察行定义，不借窗口推断缺失日期、真实状态或历史关系。

这是实现前研究和候选技术契约，不是新能力验收。完整 P1 的五类必需范围仍见[原计划](../../../../ossie-duckdb-plan.md)；状态变化与历史有效期的业务问题仍等待用户答复。没有调用模型或推送。

## 规范、解析与执行分开

固定来源为 Ossie `8dd6732da354f22ca71f16d82626a46039ecdcd9`，版本 `0.2.0.dev0`。本轮读本地保存的[本体规范](../sources/apache-ossie/ontology/ontology.md)和[表达式规范](../sources/apache-ossie/core-spec/expression_language.md)，没有把当前上游变化引入冻结契约。

本体规范已有 relationship `derived_by`、`requires` 和角色绑定、集合及无 NULL link 的定义。它的关系调用示例支持 `Person.parent_of(descendant)` 这一形状；不能仅凭对象映射或 SQL parser 接受，认定 `DailyObservation.user = User` 已有正确实体语义。候选因此使用：

```text
DailyObservation.classification_value >= 10 AND DailyObservation.user(User)
DailyObservation.qualified_user(User)
```

表达式规范列出 `LAG` 和窗口聚合、观察行 `ROWS` frame。窗口放置仍由具体查询接口规定；规范列举不表示当前 population 已绑定或执行。

[实际报告](oracle.json)分别记录固定 schema 校验、四个 SQL parser AST、普通 SQL 对照和当前插件拒绝。候选含约束时拒绝 `UNSUPPORTED_CAPABILITY`；去掉约束单独声明派生关系仍拒绝同码；只加入窗口字段拒绝 `RULE_REJECTED`。三次拒绝均保留原 snapshot。报告中的 parser 树不证明本体角色已经绑定。

## 独立计算揭示的边界

关系对照使用既有 23 行观察样例，根身份为完整 `(User, date, product)`，目标身份为带类型的 `User`。阈值 10 产生 18 个完整 link，阈值 20 产生 7 个；同一个 K 的四个日期/产品来源保留四条关系。两个相同推导按完整 link 合并成集合；来源主键重复则是输入错误，不能靠关系去重修复。

两个依赖层级由手写普通 SQL 降低执行，并与独立 TypeScript 集合比较。它证明测试 oracle 和候选语义可区分阈值/粒度，尚未证明插件执行依赖图，也没有证明任意非递归图。

约束样例显式使用 `classification_value IS NULL OR classification_value >= 0`，使样例谓词无 UNKNOWN。加入不合格负值来源后，全根对象域有一次违反，先按合格条件过滤却看不到违反。因此 `requires` 应在完整声明人口上验证，不能充当 WHERE。无 NULL guard 的比较有一个 UNKNOWN；本轮没有替用户决定其业务处理方式。

[收入事实](revenue.csv)粒度是 User/date，[成本事实](cost.csv)是 User/date/product，单位均为样例 USD。各自聚合至 User 后，A 为 375.00、85.00、差额 290.00；直接以 User/date 连接后收入变成 525.00。独立整数分计算确认该反例。研究的组合域为两边都有事实的 User：A/B/C，D/E 不进入；C 的全 NULL 金额保持 NULL。该域是显式候选，不能代表全部注册用户或缺失金额等于零。

在共同域内，收入至少 100 的集合为 A，成本小于 80 为 B；交集空、并集 A/B、排除集 A。完整成员由独立集合得到，普通 SQL 另验证人数。当前样例不定义比率；后续接口若提供比率，必须另声明分子、分母、单位及空分母行为。

跨 1 月/2 月同一 User 的 `LAG` 和当前行加前一观察行 SUM 与逐分计算相同；A 的 2 月 1 日前值为 200、两行和为 250。只有观察行，绝不能解读成“前一天”或“两天连续合格”。排序键在样例中唯一；实现必须验证唯一排序或拒绝歧义。

## 下一切片的候选技术契约

选择新的有限关系 profile，而不是直接放宽旧 Bundle，也不在本轮建立通用图引擎。当前 Bundle 只有一个根、派生概念和资格规则；将多个关系规则压到一个资格条件会失去依赖、来源和约束人口。新的 RelationProgram 可复用内容哈希、冻结捕获、原子发布、取消和预算基础设施，但独立保存声明和解析结果。

首个支持路径限定为现观察根到 User 的有类型、单目标关系，允许多个非递归推导依赖并在拓扑序执行。User 来自声明的映射绑定，不能用任意同值字符串充当目标实体。根完整身份与目标类型/身份始终保留，缺少 link 不生成 NULL 目标或默认用户。名称只是引用标识，不能把 `qualified_user` 这个名称隐式绑定到旧 QualifiedObservation 规则。

绑定检查包括未知关系/角色/概念、类型或角色数量不符、循环、目标多值违反单值声明、来源重复、映射与推导同时定义的冲突。声明重排、改名及上游阈值改变必须保持依赖的真实含义。资源候选为最多 32 个派生关系、依赖深度 16、源行 10,000、每个完整关系集合 10,000 links、捕获总字节 16 MiB；最终接口预算需根据实际编码和执行证据冻结，不能当作已经通过的边界。

约束首片限制为明确处理 NULL 的有限谓词形式，并检查完整声明人口。需要证明该语法在声明类型下总有 TRUE/FALSE，无法证明时拒绝，避免静默把 UNKNOWN 解释成业务违反。关系上的 `requires` 在完整已形成的 link 集合验证；空集合上约束成立不代表存在来源，存在性要求需独立声明。任意表达式、递归、路径闭包、跨事实关联及 UNKNOWN 的通用业务策略不在首片支持范围，仍保留在 P1 后续研究/实现范围。

执行必须在关系图与约束全部验证后原子发布。失败、取消或资源耗尽保留旧 snapshot；对象查询返回完整关系成员与身份，解释输出实际依赖、类型、约束人口及执行阶段，发现声明支持和拒绝边界。先完成原生/SQL/独立 link oracle，再接 MCP 和无模型验收；不能以本研究 SQL 代替这些证据。

## 后续衔接与未完成项

多事实组件保留各自源身份和粒度，先按目标 User 归约再组合；没有 revenue 产品维度就拒绝对其做产品分配或过滤。交/并/排除人口在明确共同域内归约，不复用观察行数量当用户分母。它需要新的声明绑定及真实插件测试，当前全未实现。

窗口组件只开放实际用例需要的 `LAG(value,1,NULL)` 和有限 `SUM ... ROWS`，明确分区、唯一排序、帧及 NULL 行为。不得把任意 WindowExpression 透传；字段与指标的允许放置、重复/缺键、预算及计划语义都需要实现证据。它与依赖图、跨事实部分衔接，不能以原每日日期归约冒充窗口支持。

每日 TRUE/FALSE/UNKNOWN 观察状态、有限半开 DATE 单值历史关系仍待业务决策。等待期间推进关系/约束、混合粒度和观察行窗口的独立技术工作。完整 P1 还需要所有新能力对应对象/解释/发现/MCP、旧三个 profile 回归、当前产物质量与 tidy、最终需求审计及待推历史检查。阶段没有完成。

## 证据及失败保留

可重复脚本为 [research_p1_program.ts](../../../../scripts/research_p1_program.ts)，需显式传入产物和输出路径；研究命令使用 Bun `--no-env-file`。产物 SHA 在报告中，C++ 未改变，不宣称本轮重新构建或重跑全部原生回归。重复运行应选择新的报告/日志路径，避免覆盖原始报告。

首版七检查报告及日志保留，最终八检查报告增加关系/窗口隔离拒绝。三份 SQL 探索失败日志分别为不存在的 `COLLATE binary` 写法、保留字 `target` 未显式声明别名、`cost` 缺 `AS`；修正使用独立字节序集合比较及显式别名，不改变 oracle。窗口错误码预期失败日志保留，按当前真实 `RULE_REJECTED` 精确验证，没有放宽为任意错误即通过。首次参数形式 `json_serialize_sql(?)` 被 DuckDB 特殊 binder 拒绝的诊断来自工具输出；改为安全转义的常量表达式，不声称已保存该次原始文件。
