# 非递归关系绑定器：实施与验证范围

本工作包实现 `BindRelationProgram`，保存带类型的根/目标声明、确定的拓扑顺序、依赖及约束 AST，并生成可由 DuckDB 绑定的有限标量谓词。55 个直接原生检查通过。它尚未接入新 profile 的加载、捕获和公开查询；旧三个 profile 仍拒绝本研究中的派生关系定义。完整 P1 没有完成。

入口在 [relation_program.hpp](../../../../src/include/ossie/relation_program.hpp)，实现为 [relation_program.cpp](../../../../src/population/relation_program.cpp)。调用者必须先提供已校验的声明映射；执行前再确认冻结源的实际类型、完整根 tuple 唯一性和唯一 User 目标身份。当前函数不读取数据、不验证数据约束成立、不发布 snapshot。声明的类型检查不等于实际源类型绑定。

支持单根到同一映射 User 的 `ManyToOne` 关系。规则只允许显式 `root.relation(User)`、声明整数字段与可表示的非 NULL 整数常量 `>=` 比较、AND/OR。每条规则及每个可能成功的 OR 分支必须有正向 User 绑定；不同推导规则以 OR 合并。依赖调用使用 upstream predicate `IS NOT DISTINCT FROM TRUE`，将未知资格解释为没有 link；它是关系存在性，不是用户观察状态的三值业务定义。绑定结果记录完整根类型和目标类型，实际对象执行仍必须携带完整根身份及映射目标值。

此专用形状允许谓词降低，因为所有合法分支绑定同一个已映射目标。它不表示任意关系可降低成布尔值，也不提供候选实体扩展、连接或其他目标域。没有关系调用的标量资格规则、未锚定 OR、否定关系、实体等号、字面量角色、坏引用、非根调用、额外角色、聚合修饰、任意函数、窗口/子查询/参数均拒绝。

当前标识符只接受未加引号的 ASCII 名称，并显式按不区分大小写查找；大小写重名及映射/标量/派生关系遮蔽拒绝。带引号标识符拒绝，不能宣称已实现上游 quoted exact 语义。物理映射由调用者显式提供，生成 ColumnRef AST，不能通过返回任意表达式绕过白名单。

约束只接受同一规范整数字段上的 `IS NULL OR field >= constant` 与 `IS NOT NULL AND field >= constant` 两种形式，可交换两个分支顺序。绑定比较前验证常量可表示于声明整数类型；没有隐式字符串比较、不受控 cast 或 NULL 常量。两种约束分别允许 NULL、拒绝 NULL。它们在已确认实际类型的前提下有完整 TRUE/FALSE 真值表；更广泛 UNKNOWN 业务策略没有默认实施。根和 link 约束分别保留，后续执行须在各自完整人口上验证，不能拿资格 WHERE 过滤代替，也不能因空 link 集合满足约束推断存在性。

边界为 1–32 个派生关系、最多 16 个依赖层级、每关系 1–8 个规则及最多 8 个约束、最多 8 个根约束。每输入表达式最多 16 KiB/1024 节点/深度 32，全部规则及约束原始文本共最多 128 KiB。每关系展开最多 1024 节点，总已分配谓词与约束节点最多 32768；在复制上游树前收费检查，避免先分配超大展开树。最终 AST 另验深度 32。它们是内部绑定预算；公开请求、实际链接集合、捕获及结果编码预算仍需新 profile 集成后实测。
