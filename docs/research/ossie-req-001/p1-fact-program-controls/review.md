已实现内部 `FactProgram` 类型绑定和阶段化查询 AST，78 项原生检查通过。它接收明确的映射角色、实际投影类型和两个来源 TableRef；还没有新的可加载 profile 或公开查询接口。不能把此结果称作整个 P1 完成，也不能声称源数据完整身份、冻结生命周期或同事务捕获已经通过。

沿 OSSIE-REQ-001 和[实施契约](../p1-program-research/implementation-contract.md)，每个 SUM/COUNT 叶节点只能来自一个明确事实字段；金额组合要求相同显式币种和 scale，金额实际类型限 DECIMAL(18,2)。分别归约至 User 后连接，共同域按两边事实行存在定义。AVG、COUNT(*)、跨事实聚合叶节点、嵌套、修饰聚合、比率及金额/人数混算拒绝。原子人口条件归一为 TRUE 成员集合，再执行交、并、差。

实际 DuckDB 查询得到 A 收入375、成本85、差额290，原始明细连接反例得到收入525；B为80/30/50。共同域保留全NULL的C，排除单侧D/E；COUNT(User)与COUNT(amount)对C分别为1和0。新增N收入150而成本NULL，TRUE集合差保留N，普通nullable NOT反例丢失N。成员检查比较完整身份，实际输出类型为DECIMAL(38,2)/BIGINT。只声明一边指标时，另一事实依然贡献存在域；另一事实为空时共同域为空。

窗口仅支持User/date来源上的显式 `LAG(value,1,NULL)` 和 `SUM ROWS n PRECEDING..CURRENT ROW`，n在0..366，最多n+1个观察行。先全来源计算，再显示日期筛选；稀疏日期下A在2月1日的前值200、两行和250。0前序只取当前行，366前序在400行实际输入上最多累计367行。NULL前值不会被跳过，无前行与前值NULL都返回NULL；不据此宣称状态变化或日历补齐。
